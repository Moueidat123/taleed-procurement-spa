# Phase 0 — read-only discovery and implementation decisions

Read the master contract. This phase permits repository/ref-source inspection and discovery documentation only. No package installation, scaffolding, service startup, migrations, cloud connection, secrets access, remote push or deployment.

Inspect the actual checkout against the uploaded-file manifest. Inventory routes, approved three-role flows, domain rules, persistence, tests, lockfiles, deployment workflow and active nested instructions. Review the source workbook/documentation and note any files that are missing. Treat the 28-test evidence in this package as the earlier review result, not a run you performed.

Inspect bounded, authorized sibling Survey/ICTTool/Sustainability source where available. Read examples/scripts without dumping secrets. Do not copy whole infrastructure, SQL Server/managed-DB-only assumptions, a Pro dependency, Vue replacement, application approval workflow or production identifiers. Record actual paths and reuse/adapt/reject reasons, including storage/backup/dry-run gaps.

Verify current official Core limits and independent-auth guard guidance, compatible dependency choices, MySQL model and proposed package licensing. Propose the selected backend/React boundaries, route table, session/provider/broker separation, schema and atomic transitions, Docker layout, durable-data inventory, no-staging operating approach and phased tests. Surface source-content approval separately from concept approval.

Write `docs/production/discovery.md`, `docs/production/reuse-matrix.md`, and `docs/production/decisions.md`, plus update the handoff. Clearly mark evidence versus proposed defaults versus externally unverified facts. Local reference unavailability does not require abandoning the selected baseline.

Stop with an actionable Phase 1 plan and at most the genuine architecture blockers. Do not ask for known fields that a permitted local source read can resolve. Do not start coding yet.
